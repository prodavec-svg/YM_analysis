# Документация Python-скриптов

В папке `scripts/` находятся три исполняемых модуля ETL-контура Yambda:

1. `build_marts.py` читает сырой parquet и собирает три витрины.
2. `validate_marts.py` проверяет витрины и сверяет их с исходником.
3. `build_visualizations.py` строит графики и аналитический отчёт из витрин.

Все пути вычисляются относительно корня репозитория, поэтому команды можно
запускать из корня `YM_analysis` независимо от абсолютного расположения клона.

## Общая схема работы

```text
data/raw/likes.parquet
        │
        ▼
scripts/build_marts.py
        │
        ├── data/marts/mart_daily_metrics.parquet
        ├── data/marts/mart_user_segments.parquet
        └── data/marts/mart_content_health.parquet
                         │
            ┌────────────┴─────────────┐
            ▼                          ▼
scripts/validate_marts.py   scripts/build_visualizations.py
                                       │
                                       ├── reports/README.md
                                       └── reports/figures/*.png
```

Установка зависимостей:

```powershell
python -m pip install -r requirements.txt
```

Рекомендуемый полный запуск:

```powershell
python scripts/build_marts.py --input data/raw/likes.parquet
python scripts/validate_marts.py --input data/raw/likes.parquet
python scripts/build_visualizations.py
```

## `build_marts.py`

### Назначение

Скрипт реализует ETL-пайплайн на ленивом API Polars. Исходник открывается через
`pl.scan_parquet()`, преобразования формируются как `LazyFrame`, а агрегации
выполняются через `collect(engine="streaming")`. Перед заменой целевого файла
готовая витрина записывается во временный parquet, поэтому незавершённый расчёт
не повреждает предыдущий результат.

### Интерфейс командной строки

```powershell
python scripts/build_marts.py `
  --input data/raw/likes.parquet `
  --output-dir data/marts
```

| Аргумент | Обязательный | Значение |
|---|---|---|
| `--input PATH` | Нет | Путь к исходному parquet. Без аргумента скрипт ищет известные имена в `data/raw/` и корне проекта. |
| `--output-dir PATH` | Нет | Каталог витрин. По умолчанию `data/marts/`. |
| `--skip-validation` | Нет | Пропускает автоматическую постпроверку. Использовать только для диагностики. |

### Ожидаемая схема исходника

| Поле | Тип | Назначение |
|---|---|---|
| `uid` | целочисленный | Идентификатор пользователя. |
| `item_id` | целочисленный | Идентификатор трека. |
| `timestamp` | целочисленный | Номер пятисекундного временного бина. |
| `is_organic` | целочисленный 0/1 | `1` — самостоятельное обнаружение, `0` — рекомендация. |

Функция `scan_source()` проверяет наличие и целочисленный тип обязательных
полей, затем приводит идентификаторы к `UInt32`, время к `UInt64`, а флаг к
`UInt8`.

### Формируемые витрины

#### `mart_daily_metrics.parquet`

Зерно: одна строка на условный день. День вычисляется как
`timestamp // 17_280`, поскольку сутки содержат 17 280 пятисекундных бинов.

| Поле | Расчёт |
|---|---|
| `time_period` | Индекс условного дня. |
| `dau` | Число уникальных `uid`. |
| `total_interactions` | Количество строк за день. |
| `organic_ratio` | Среднее `is_organic`, то есть доля органических лайков. |

#### `mart_user_segments.parquet`

Зерно: один пользователь.

| Поле | Расчёт |
|---|---|
| `total_likes` | Все взаимодействия пользователя. |
| `organic_likes` | Сумма `is_organic`. |
| `algo_likes` | `total_likes - organic_likes`. |
| `segment` | Поведенческий сегмент. |

Правила применяются сверху вниз:

1. `Cold`: меньше пяти лайков.
2. `Explorer`: доля органических лайков строго больше 70%.
3. `Passive`: доля алгоритмических лайков строго больше 70%.
4. `Mixed`: все остальные пользователи.

#### `mart_content_health.parquet`

Зерно: один трек. После агрегации треки сортируются по `total_likes` по
убыванию, а равенства разрешаются по `item_id`. Такое ранжирование обеспечивает
воспроизводимые границы уровней:

- `Head`: первые `ceil(N × 1%)` треков;
- `Torso`: позиции после Head до `ceil(N × 20%)`;
- `Tail`: оставшиеся 80% каталога.

### Функции

| Функция | Ответственность |
|---|---|
| `parse_args()` | Разбирает CLI-аргументы. |
| `resolve_input()` | Находит и проверяет исходный parquet. |
| `scan_source()` | Проверяет схему и возвращает нормализованный `LazyFrame`. |
| `daily_metrics()` | Строит ленивый план дневной витрины. |
| `user_segments()` | Строит пользовательские агрегаты и сегменты. |
| `content_health()` | Считает популярность, органическую долю и tier трека. |
| `write_mart()` | Выполняет streaming-расчёт и атомарно записывает parquet с Zstandard-сжатием. |
| `main()` | Координирует полный ETL и вызывает валидатор. |

## `validate_marts.py`

### Назначение

Скрипт выполняет независимые проверки файлов и бизнес-инвариантов. При любой
ошибке он завершает работу с ненулевым кодом и понятным исключением. При успехе
печатает основные объёмы, доли сегментов и размеры файлов.

Запуск:

```powershell
python scripts/validate_marts.py `
  --input data/raw/likes.parquet `
  --marts-dir data/marts
```

| Аргумент | Обязательный | Значение |
|---|---|---|
| `--input PATH` | Да | Исходный parquet для перекрёстной сверки. |
| `--marts-dir PATH` | Нет | Каталог витрин; по умолчанию `data/marts/`. |

### Проверки

- наличие всех трёх parquet-файлов;
- точное совпадение обязательных столбцов;
- размер каждого файла не более 10 МиБ;
- отсутствие пропусков в исходнике и витринах;
- бинарность `is_organic`;
- уникальность ключей `time_period`, `uid`, `item_id`;
- положительный DAU;
- диапазон всех долей от 0 до 1;
- совпадение числа взаимодействий во всех витринах с исходником;
- совпадение числа пользователей и треков;
- равенство `organic_likes + algo_likes = total_likes`;
- восстановление исходного числа органических событий из каждой витрины;
- правильность сегмента каждой пользовательской строки;
- сумма долей пользовательских сегментов 100%;
- точное соответствие размеров Head, Torso и Tail заданным процентилям.

### Функции

| Функция | Ответственность |
|---|---|
| `_collect()` | Выполняет ленивый план streaming-движком. |
| `_scalar()` | Безопасно извлекает скаляр из результата проверки. |
| `_check_files()` | Проверяет наличие, размер и схему файлов. |
| `validate_marts()` | Выполняет полный набор проверок и возвращает словарь метрик. |
| `parse_args()` | Разбирает CLI-аргументы автономного запуска. |

Функцию `validate_marts()` можно импортировать из другого Python-кода. При
`verbose=False` она не печатает отчёт, но по-прежнему выбрасывает исключение при
нарушении инварианта.

## `build_visualizations.py`

### Назначение

Скрипт читает готовые витрины и создаёт презентационный отчёт. Он не обращается
к сырому датасету и поэтому выполняется быстро. Для серверного и CI-запуска
Matplotlib переключается на неинтерактивный backend `Agg`.

Запуск без аргументов:

```powershell
python scripts/build_visualizations.py
```

### Результаты

| Файл | Содержание |
|---|---|
| `reports/figures/daily-activity.png` | DAU, число взаимодействий и органическая доля; исходный ряд и 30-дневное среднее. |
| `reports/figures/user-segments.png` | Доля пользователей, среднее число лайков и organic share по сегментам. |
| `reports/figures/content-health.png` | Ранговая кривая популярности, Gini и сравнение доли каталога с долей лайков. |
| `reports/README.md` | Автоматическая Markdown-сводка с графиками, таблицами и ключевыми выводами. |

### Функции

| Функция | Ответственность |
|---|---|
| `configure_style()` | Настраивает единую тёмную тему графиков. |
| `read_marts()` | Проверяет наличие и читает три витрины. |
| `finish_figure()` | Сохраняет PNG с фиксированным DPI и закрывает figure. |
| `plot_daily_activity()` | Строит три временных ряда и 30-дневные сглаживания. |
| `segment_summary()` | Считает размер, среднюю активность и organic share сегментов. |
| `plot_user_segments()` | Визуализирует состав и активность аудитории. |
| `content_summary()` | Агрегирует количество треков и лайков по tier. |
| `calculate_gini()` | Считает коэффициент Джини по популярности треков. |
| `plot_content_health()` | Строит ранговую кривую и распределение внимания. |
| `write_report()` | Генерирует `reports/README.md` из фактических метрик. |
| `main()` | Пересобирает все графики и отчёт. |

### Интерпретация Gini

Gini близкий к нулю означает равномерное распределение лайков между треками;
значение ближе к единице означает концентрацию внимания у небольшого числа
хитов. Метрика описывает распределение популярности, но сама по себе не
доказывает ошибку рекомендательной системы.

## Воспроизводимость и диагностика

- Скрипты рассчитаны на Python 3.10+ и версии библиотек из `requirements.txt`.
- Сырой и очищенный датасеты находятся вне Git; витрины и графики отслеживаются.
- Для просмотра плана Polars перед выполнением можно вызвать `plan.explain()`.
- Если сборка завершилась, но проверка упала, не используйте
  `--skip-validation` как постоянное решение: сначала устраните нарушенный
  инвариант.
- После изменения правил витрин запускайте все три команды полного цикла и
  проверяйте `git diff --check` перед коммитом.
