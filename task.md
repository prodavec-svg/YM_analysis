# 📋 Задача: Разработка витрин данных (Data Marts) для дашборда Yambda

## 🎯 Цель

Преобразовать сырые логи взаимодействий (50+ млн строк) в агрегированные, легковесные таблицы (витрины данных). Эти витрины станут фундаментом для интерактивного дашборда продукта, обеспечив его мгновенную загрузку и фильтрацию без переполнения оперативной памяти.

## 📥 Входные данные

* **Источник:** Локальные файлы `likes.parquet` (или `multi_event.parquet`).
* **Схема сырых данных:** `uid` (uint32), `item_id` (uint32), `timestamp` (uint32, бины по 5 секунд), `is_organic` (uint8).

## 📤 Ожидаемый результат (Deliverables)

1. Набор Python-скриптов (с использованием `Polars`), описывающих логику трансформации (ETL-пайплайн).
2. Физические `.parquet` или `.csv` файлы витрин в папке `data/marts/`.
3. Файлы витрин весят не более 5-10 МБ и закоммичены в GitHub репозиторий проекта.

## 🛠️ Структура витрин и логика сборки

Необходимо разработать и собрать три ключевые витрины:

### Витрина 1: `mart_daily_metrics` (Динамика состояния продукта)

**Назначение:** Отрисовка главных графиков дашборда (DAU, активность) во времени.

* **Зернистость (Granularity):** 1 строка = 1 временной период (день/час). *(Примечание: так как `timestamp` в датасете — это дельты по 5 секунд, нужно конвертировать их в условные "дни", разделив на `(24 * 60 * 60 / 5)`).*
* **Необходимые поля:**
* `time_period` (индекс дня или часа)
* `dau` (Daily Active Users) — количество уникальных `uid`.
* `total_interactions` — общее количество лайков/прослушиваний.
* `organic_ratio` — доля лайков, где `is_organic == 1`.



### Витрина 2: `mart_user_segments` (Разрезы по аудитории)

**Назначение:** Фильтрация данных на дашборде по типу поведения пользователей и анализ вовлеченности.

* **Зернистость:** 1 строка = 1 пользователь (`uid`).
* **Необходимые поля:**
* `uid` — идентификатор пользователя.
* `total_likes` — всего поставлено лайков.
* `organic_likes` — лайки из самостоятельного поиска.
* `algo_likes` — лайки из рекомендаций.
* `segment` (строковое поле) — логика:
* Если `total_likes` < 5 ➡️ `"Cold"` (Холодный / Новичок).
* Если `organic_likes` / `total_likes` > 0.7 ➡️ `"Explorer"` (Исследователь).
* Если `algo_likes` / `total_likes` > 0.7 ➡️ `"Passive"` (Пассивный слушатель).
* Остальные ➡️ `"Mixed"` (Смешанный).





### Витрина 3: `mart_content_health` (Анализ контента и точек роста)

**Назначение:** Иллюстрация проблемы Popularity Bias (насколько сильно хиты забирают на себя весь трафик).

* **Зернистость:** 1 строка = 1 трек (`item_id`).
* **Необходимые поля:**
* `item_id` — идентификатор трека.
* `total_likes` — популярность трека.
* `organic_ratio` — как часто его находят сами vs через алгоритм.
* `content_tier` (строковое поле) — логика (на основе перцентилей):
* Топ 1% по лайкам ➡️ `"Head"` (Хиты).
* Топ 2-20% ➡️ `"Torso"` (Средние).
* Остальные 80% ➡️ `"Tail"` (Нишевые/Хвост).

## 🏗️ Технические требования

1. **Инструмент:** Использовать библиотеку `Polars` в ленивом режиме (`pl.scan_parquet()`).
2. **Оптимизация:** Сборка всех агрегаций должна происходить через `.collect(streaming=True)` для защиты от Out of Memory.
3. **Организация репозитория:**
```text
YM_analysis/
├── data/
│   ├── raw/           # <-- СЮДА КЛАДЕМ СЫРЫЕ ФАЙЛЫ (Добавлено в .gitignore!)
│   └── marts/         # <-- СЮДА СОХРАНЯЕМ ВИТРИНЫ (Эти файлы коммитим в Git)
├── scripts/
│   └── build_marts.py # Скрипт сборки витрин
├── .gitignore
└── README.md

```
